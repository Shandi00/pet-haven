# Pet Haven 資料庫結構（DB Schema）

- **對應任務**：03 架構、流程與資料模型；08 配對欄位補齊（欄位定義的依據）
- **資料庫**：MongoDB Atlas，資料庫名稱由 `MONGODB_DB` 設定（預設 `pet_haven`；測試用 `pet_haven_test`）
- **來源**：2026-11-25 依 `dev` 分支程式整理。Pet、Adoption、Message、Notification、Post、Comment 的欄位表**由 `backend/app/models/*.py` 的 `SCHEMA` 自動產生**；User、LicensedShop 在 FastAPI 版沒有 `SCHEMA`，依舊版 Mongoose model（`backend-legacy/models/`）與 FastAPI 實際寫入的欄位整理。與程式不一致時以程式為準，並回頭修正本文件。
- **本期新增**：只有 `User.gameProfile`、`User.matchFeedback` 兩個欄位（標示 🆕，尚未實作，由後端計畫 Task 4 加入預設值）。其他 collection 不改。
- **相關文件**：[現況架構](現況架構.md)（ERD 與認養狀態圖）、[新增 API 契約](../api/新增API契約.md)、[API 清單](../api/API清單.md)

## 寫法說明

- 欄位路徑用 `.` 表示巢狀物件，`[]` 表示陣列；`array<object>` 的子欄位列在下一行。
- 「必填」打勾的欄位在寫入前由 model 的 `SCHEMA` 驗證（`app/core/schema.py`，錯誤訊息格式同 Mongoose）。
- 每份文件另有 `_id`（ObjectId）、`createdAt`、`updatedAt`；陣列中的子文件也有自己的 `_id`。
- 參照其他 collection 的欄位型別寫成 `ObjectId → Model`。

## 總覽

| Collection | Model | 用途 | 程式 |
|---|---|---|---|
| `users` | User | 使用者（認養者、送養者、收容機構、管理員）與配對檔案 | `app/models/user.py` |
| `pets` | Pet | 送養動物（含政府匯入資料） | `app/models/pet.py` |
| `adoptions` | Adoption | 認養申請 | `app/models/adoption.py` |

| `notifications` | Notification | 通知 | `app/models/notification.py` |
