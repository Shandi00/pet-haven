# T13 Top 3 配對與 AI 理由 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 實作 `GET /api/matching/top3`、`POST /api/matching/feedback`、`DELETE /api/matching/feedback`，依契約的硬條件、既有計分與回饋重排取前 3 名，每隻附理由。

**Architecture:** 計分沿用 `app/services/advanced_matching.py`；新增 `app/services/top3.py` 放篩選、重排與組裝；理由由 `app/services/ai_explain.py` 的 `explain()` 產生。本計畫先建立 `ai_explain.py` 的規則理由（`rule_reason`）與只回規則理由的 `explain()`，後端組員 T12 Task 7 在同一個檔案補上 Gemini 路徑，`top3.py` 不用改。

**Tech Stack:** Python FastAPI、pymongo（async）、pytest（`api`／`make_user`／`make_pet` fixture，連 `pet_haven_test`）

**Spec:** [新增 API 契約](../../api/新增API契約.md) §0（硬條件、排序與回饋重排）、§2、§3、§5、附錄 `matchFeedback`

## Global Constraints

- 回應格式：成功 `{ "success": true, "data": ... }`；失敗 `{ "success": false, "message": "繁中訊息" }`（`HTTPException` 會由 `app/responses.py` 轉成這個格式）。
- 三支 API 都要登入（`Depends(current_user)`），`user`／`shelter`／`admin` 都可用，只讀寫**自己的**回饋。
- id 不合法回 400，動物不存在回 404，不可 500。
- `reason`：`summary` 最多 80 字；`highlights`、`cautions` 各 0–3 筆；只引用 §0 白名單欄位；`source` 為 `"ai"` 或 `"rule"`。
- `matchFeedback` 存在 `User.matchFeedback`：`[{ pet: ObjectId, verdict: "like" | "dislike", createdAt }]`，同一隻只留最新一筆。欄位預設值由後端 Task 4 加到 `new_user_doc`；本計畫讀取時一律 `user.get("matchFeedback") or []`，不改 `models/user.py`，避免衝突。
- 每支路由寫 `summary`（Swagger）；log 不記個資。

## Review Focus

1. 按過「不適合」的動物之後被刪除或已被認養 → `avoided` 略過牠，不能 500（Task 3 測試）。
2. 舊資料動物沒有照片、`goodWith` 沒填 → `photo` 為 `""`；`goodWith` 為 `null` 不篩掉，並寫進 `cautions`（Task 1、2 測試）。
3. 符合條件的動物不足 3 隻或為 0 → `items` 少於 3 筆或空陣列（Task 3 測試）。
4. 同一隻先按「不適合」再按「適合」→ 只留最新的 `like`，牠不再出現在 `avoided`，也不再造成扣分（Task 3 測試）。
5. body 缺 `verdict`、`petId` 不是字串、body 不是 JSON 物件 → 400，不是 500（Task 3 測試）。

## 暫不做（等後端組員交付後接上）

- 速率限制：T12 Task 5 的 `matching_limiter.check(user_id)` 完成後，加到 `GET /top3`、`POST /feedback`。
- 3 隻理由整體不超過 `LLM_TIMEOUT_SECONDS`：T12 Task 7 加入 Gemini 時，在 `build_top3` 的 `asyncio.gather` 外包 `asyncio.wait_for`，逾時改用 `rule_reason`。

### Task 1：規則理由（`ai_explain.py`）

**Files:**
- Create: `backend/app/services/ai_explain.py`
- Test: `backend/tests/test_ai_explain.py`

**Interfaces:**
- Produces: `def rule_reason(pet: dict, user: dict) -> dict`，回傳 `{ "summary", "highlights", "cautions", "source": "rule" }`。
- Produces: `async def explain(pet: dict, user: dict) -> dict`，目前直接回傳 `rule_reason(pet, user)`；T12 Task 7 在此加 Gemini 路徑。

規則：
- 用 `calculate_match(pet, user)`；`highlights` = `analysis.strengths + analysis.highlights` 前 3 筆。
- `cautions` = 先放 `goodWith` 不確定的提醒，再接 `analysis.concerns`，取前 3 筆。不確定的提醒：使用者 `environmentProfile.hasChildren` 為真且動物 `personality.goodWith.children` 為 `None` → `"還不確定{name}能否和小孩相處，建議先向送養人確認"`；`hasOtherPets` 與 `goodWith.otherPets` 同理 → `"還不確定{name}能否和其他寵物相處，建議先向送養人確認"`。
- `summary`：有 `strengths` 時為 `f"{name}：{'、'.join(strengths[:2])}。"`，沒有時為 `f"{name}符合你的基本條件，可以進一步了解。"`；超過 80 字時截斷到 80 字。**不寫分數**：`rule_reason` 不知道回饋扣分，寫分數會和卡片上的 `score` 不一致。

### Task 2：篩選、重排與組裝（`top3.py`）

**Files:**
- Create: `backend/app/services/top3.py`
- Test: `backend/tests/test_top3.py`

**Interfaces:**
- Consumes: `ai_explain.explain(pet, user)`、`advanced_matching.calculate_match`、`match_level`。
- Produces（純函式，不連資料庫）：
  - `def passes_hard_rules(pet: dict, user: dict, disliked_ids: set) -> bool`：契約 §0 硬條件 2–6（條件 1 由查詢負責）。
  - `def penalty(pet: dict, disliked_pets: list[dict]) -> int`：每隻 `species` 與 `personality.activityLevel` 都相同（且 `activityLevel` 有值）的不適合動物扣 5，最多 15；不扣自己。
  - `def rank(pets: list[dict], user: dict, disliked_pets: list[dict]) -> list[dict]`：回傳 `[{ "pet", "score": int, "matchLevel": str }]` 前 3 名。`score = max(0, math.floor(matchScore - penalty + 0.5))`（四捨五入；Python 的 `round()` 是銀行家捨入，扣 5 分後可能差 1），`matchLevel = match_level(score)["level"]`；排序鍵 `(score, createdAt)` 由大到小，`createdAt` 缺少時視為最舊。
  - `def pet_summary(pet: dict) -> dict`：契約 §2 的 `pet` 精簡欄位；`photo` 取 `isPrimary` 的照片，沒有就第一張，沒有照片為 `""`。
  - `def avoided_note(pet: dict) -> dict`：`{ "petId", "name", "note": "已避開：{name}（{物種}，活動量{低/中等/高}），並降低相似動物的排序" }`；物種：dog 狗、cat 貓、rabbit 兔、bird 鳥、hamster 倉鼠、guinea-pig 天竺鼠、other 其他；沒有活動量時括號內只寫物種。
- Produces（連資料庫）：`async def build_top3(user: dict) -> dict`，回傳契約 §2 的 `data`：`{ items, avoided, generatedAt }`。`user` 是完整使用者文件。`avoided` 依 `matchFeedback` 的 `createdAt` 由新到舊，略過已不存在的動物；3 隻的理由用 `asyncio.gather(explain(...))` 並行產生。

```python
from datetime import datetime, timezone
from bson import ObjectId
from app.services import top3

def pet(**kw):
    base = {"_id": ObjectId(), "name": "小白", "species": "dog", "size": "medium", "ageCategory": "adult",
            "personality": {"activityLevel": "high", "traits": [], "goodWith": {}},
            "createdAt": datetime(2026, 11, 1, tzinfo=timezone.utc)}
    base.update(kw)
    return base

def test_hard_rules():
    user = {"environmentProfile": {"hasChildren": True, "hasAllergies": True},
            "recommendationProfile": {"species": ["dog"]}}
    ok = pet()
    assert top3.passes_hard_rules(ok, user, set())
    assert not top3.passes_hard_rules(ok, user, {ok["_id"]})
    assert not top3.passes_hard_rules(pet(personality={"goodWith": {"children": False}}), user, set())
    assert top3.passes_hard_rules(pet(personality={"goodWith": {"children": None}}), user, set())
    assert not top3.passes_hard_rules(pet(species="cat"), {"environmentProfile": {"hasAllergies": True}}, set())
    assert not top3.passes_hard_rules(pet(species="rabbit"), user, set())
    assert top3.passes_hard_rules(pet(species="rabbit"), {"recommendationProfile": {"species": []}}, set())

def test_penalty_caps_at_15_and_needs_same_species_and_activity():
    target = pet()
    same = [pet() for _ in range(4)]
    assert top3.penalty(target, same) == 15
    assert top3.penalty(target, [pet(species="cat"), pet(personality={"activityLevel": "low"})]) == 0
    assert top3.penalty(target, [target]) == 0

def test_rank_tie_breaks_by_newer_and_limits_to_3():
    pets = [pet(name=str(i), createdAt=datetime(2026, 11, i + 1, tzinfo=timezone.utc)) for i in range(5)]
    ranked = top3.rank(pets, {}, [])
    assert [r["pet"]["name"] for r in ranked] == ["4", "3", "2"]
    assert all(isinstance(r["score"], int) for r in ranked)

def test_pet_summary_photo_and_avoided_note():
    assert top3.pet_summary(pet())["photo"] == ""
    photos = [{"url": "/a.jpg"}, {"url": "/b.jpg", "isPrimary": True}]
    s = top3.pet_summary(pet(photos=photos))
    assert s["photo"] == "/b.jpg" and s["activityLevel"] == "high" and isinstance(s["_id"], str)
    assert top3.avoided_note(pet(name="阿福"))["note"] == "已避開：阿福（狗，活動量高），並降低相似動物的排序"
```

**Interfaces:**
- Consumes: `top3.build_top3(full_user)`、既有 `_full_user(user)`、`oid()`。
- Produces：
  - `GET /api/matching/top3`（summary「Top 3 推薦與理由」）→ `{ success, data: build_top3(...) }`。
  - `POST /api/matching/feedback`（summary「適合／不適合回饋」）：body 不是物件、`verdict` 不在 `like`／`dislike`、`petId` 不是字串或 `oid()` 為 `None` → 400 `"參數錯誤"`；動物不存在 → 404 `"找不到指定的寵物"`。寫入：讀出 `matchFeedback`，移除同一隻後附加 `{ pet, verdict, createdAt: now }`，`$set` 整個陣列。`dislike` 回傳 `build_top3` 的結果（重新讀使用者）；`like` 回傳 `{ "recorded": true }`。
  - `DELETE /api/matching/feedback`（summary「清除自己的回饋紀錄」）→ `{ "cleared": 原本筆數 }`，`$set` 為 `[]`。

```python
def test_top3_requires_login(api):
    assert api.get("/api/matching/top3").status_code == 401

def test_top3_filters_ranks_and_handles_few_pets(api, make_user, make_pet):
    owner, _ = make_user("shelter")
    _, h = make_user(environmentProfile={"hasChildren": True})
    assert api.get("/api/matching/top3", headers=h).json()["data"]["items"] == []
    make_pet(owner, name="怕小孩", personality={"activityLevel": "high", "goodWith": {"children": False}})
    make_pet(owner, name="已認養", adoptionStatus="adopted")
    make_pet(owner, name="可以")
    data = api.get("/api/matching/top3", headers=h).json()["data"]
    assert [i["pet"]["name"] for i in data["items"]] == ["可以"]
    item = data["items"][0]
    assert item["reason"]["source"] == "rule" and item["pet"]["photo"] == "" and data["avoided"] == []
    assert item["reason"]["cautions"][0].startswith("還不確定可以能否和小孩相處")

def test_dislike_reranks_and_like_overrides(api, make_user, make_pet):
    owner, _ = make_user("shelter")
    _, h = make_user()
    a = make_pet(owner, name="阿福", personality={"activityLevel": "high"})
    b = make_pet(owner, name="相似", personality={"activityLevel": "high"})
    make_pet(owner, name="不同", species="cat", personality={"activityLevel": "low"})
    before = {i["pet"]["name"]: i["score"] for i in api.get("/api/matching/top3", headers=h).json()["data"]["items"]}
    r = api.post("/api/matching/feedback", json={"petId": str(a["_id"]), "verdict": "dislike"}, headers=h).json()["data"]
    after = {i["pet"]["name"]: i["score"] for i in r["items"]}
    assert "阿福" not in after and after["相似"] == before["相似"] - 5 and after["不同"] == before["不同"]
    assert r["avoided"][0]["name"] == "阿福"
    assert api.post("/api/matching/feedback", json={"petId": str(a["_id"]), "verdict": "like"},
                    headers=h).json()["data"] == {"recorded": True}
    data = api.get("/api/matching/top3", headers=h).json()["data"]
    assert data["avoided"] == [] and "阿福" in [i["pet"]["name"] for i in data["items"]]

def test_avoided_skips_deleted_pet_and_feedback_is_per_user(api, make_user, make_pet, sync_db):
```
