# T14 知識庫檢索 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 實作 AI 聊天助理的檢索：`knowledge_base.search(query, k=3)`，讓 `POST /api/ai/chat`（T12 Task 6）先檢索 FAQ、只根據檢索結果回答。

**Architecture:** 單一 service `backend/app/services/knowledge_base.py`。讀 `backend/app/data/knowledge_base.json`（T11 交付），字元 bigram 比對，回傳前 3 筆；`validate()` 依契約附錄檢查格式，載入時丟掉不合格的條目。

**Tech Stack:** Python 標準函式庫；pytest。

**Spec:** [需求與展示範圍](../specs/2026-11-25-需求與展示範圍-design.md) T14；[新增 API 契約](../../api/新增API契約.md) §0「知識庫檢索」、§4、附錄「知識庫格式」。

## Global Constraints

- 查無資料時不呼叫 LLM，直接回答不知道（契約 §0）。
- 知識庫不含個資；`content` 每筆最多 500 字；`source` 必填；`id` 格式 `faq-<主題>-<三位數>`（契約附錄）。
- 介面固定：`search(query: str, k: int = 3) -> list[dict]`，每筆 `{ id, title, content, source }`（後端計畫 Task 6）。

## Task 1：檢索與格式檢查 ✅

**Files:** Create `backend/app/services/knowledge_base.py`、`backend/tests/test_knowledge_base.py`

- 分數＝問題 bigram（去掉問句詞 `STOP_BIGRAMS`）被條目「標題＋tags＋內容」涵蓋的比例；`MIN_SCORE = 0.3`；同分依 `id` 排序。
- 只取英數與中文字元計算 bigram；少於 2 個字的問題沒有 bigram，視為查無資料。
- 檔案不存在、無法解析、不是陣列：回空陣列並記 warning（只記檔名與錯誤類型）。
- `test_repo_knowledge_base_is_valid`：T11 交付檔案後自動檢查格式；未交付時 skip。

## Task 2：知識庫檢查工具 ✅

**Files:** Create `backend/scripts/check_knowledge_base.py`、`backend/tests/test_check_knowledge_base.py`；Modify `knowledge_base.py`（抽出 `ranked(query, entries)`，`search` 改用它）

整理或審核知識庫時，在 `backend/` 執行：

```bash
.venv/Scripts/python -m scripts.check_knowledge_base                          # 檢查 app/data/knowledge_base.json
.venv/Scripts/python -m scripts.check_knowledge_base 草稿.json --ask "認養要什麼條件"   # 檢查草稿並試問題
```

會列出不符合契約附錄的地方（不合格的條目不會被檢索到），並顯示每個問題檢索到的條目、分數與來源；格式正確回傳 0，有問題回傳 1。
