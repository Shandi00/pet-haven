# 前端組員任務（T09、T10、T11、T15）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成展示主線的前端畫面：配對檔案、8 題小遊戲、Top 3 推薦與回饋、AI 助理聊天，並整理 AI 知識庫內容。

**Architecture:** 小遊戲的計分寫成純函式（`utils/matchGame.js`），題目放在資料檔，畫面只負責顯示。推薦和聊天透過 `services/aiService.js` 呼叫 API，這個檔案會依 mock 開關決定用真的 API 或 `aiMock.js`，所以後端完成前就能開發和測試。

**Tech Stack:** React 18、React Router 6、Tailwind CSS 3、jest 與 React Testing Library（react-scripts 內建）、Playwright。

**Spec:** [需求與展示範圍](../specs/2026-11-25-需求與展示範圍-design.md)、[新增 API 契約](../../api/新增API契約.md)、[frontend/AGENTS.md](../../../frontend/AGENTS.md)

**開發方式：** 每個 Task 開一個分支，例如 `feat/T10-match-game`，完成後發 PR 到 `dev`。後端還沒完成時，在瀏覽器 console 執行 `localStorage.setItem('useMockData','true')` 再重新整理，就會改用假資料。

## Global Constraints

- 新頁面路徑：小遊戲 `/match-game`、推薦 `/recommendations`；兩頁都要登入，用 `services/auth.js` 的 `ProtectedRoute` 包起來。
- 畫面文字用繁體中文；先用 `components/ui/` 的元件，樣式用 Tailwind。
- 每個資料畫面都要有載入中、錯誤、沒有資料三種狀態。
- `reason.source === 'rule'` 時顯示「目前使用規則推薦」；聊天 `source === 'fallback'` 時顯示備援訊息，不能假裝是 AI 產生的。
- 不在前端呼叫 LLM，也不保存金鑰。

## Review Focus

- 連點兩下「不適合」：送出期間要停用按鈕，不能送出兩次 → Task 4 Step 1
- 所有動物都按了「不適合」，Top 3 變成空的：顯示空狀態和「重新開始」按鈕（呼叫 `resetFeedback`） → Task 4 Step 1
- 聊天送出空白訊息或超過 500 字：送出按鈕要停用，不能打 API → Task 5 Step 1
- 小遊戲做到一半離開再回來：從第 1 題重新開始，不會用半套答案寫入檔案 → Task 2 Step 1
- API 失敗（後端沒開）：顯示後端的 `message` 或「連線失敗，請稍後再試」，不能整頁白畫面 → Task 4 Step 1

### Task 2：小遊戲計分邏輯（T10）

**Files:**
- Create: `frontend/src/data/matchGameQuestions.js`、`frontend/src/utils/matchGame.js`
- Test: `frontend/src/utils/matchGame.test.js`

**Interfaces:**
- Produces:
  - `matchGameQuestions.js` 匯出 `questions` 和 `petTypes`：
    - `questions: Array<{ id, question, options: Array<{ id, label, effects, typeScore }> }>`
      - `effects` 的格式為 `{ lifestyle?: {...}, experience?: {...}, environment?: {...} }`，欄位名稱和可用值見 [API 契約第 1 節](../../api/新增API契約.md)
      - `typeScore` 的格式為 `{ [petTypeCode]: number }`
    - `petTypes: Array<{ code, label, description }>`
    - 8 題的實際內容由 T05 決定。先放以下 2 題範例，測試也依這 2 題撰寫；換成正式題目時，測試資料一起更新：

| 題目 | 選項 → `effects` ／ `typeScore` |
|---|---|
| `q1` 週末早上你通常在做什麼？ | `A` 出門爬山 → `lifestyle.activityLevel: 'high'`／`{ 'outdoor-buddy': 2 }`；`B` 在家追劇 → `'low'`／`{ 'couch-buddy': 2 }`；`C` 看心情 → `'medium'`／`{ 'balanced-buddy': 2 }` |
| `q2` 每天能陪毛孩多久？ | `A` 兩小時以上 → `lifestyle.availableTime: 'extensive'`／`{ 'outdoor-buddy': 1 }`；`B` 一小時左右 → `availableTime: 'moderate'`、`activityLevel: 'medium'`／`{ 'balanced-buddy': 1 }`；`C` 很少 → `availableTime: 'minimal'`、`activityLevel: 'low'`／`{ 'couch-buddy': 1 }` |

`petTypes`：`outdoor-buddy` 戶外冒險型、`balanced-buddy` 隨和陪伴型、`couch-buddy` 居家宅宅型。
  - `computeGameResult(questions, answers) -> { lifestyle, experience, environment, petType }`
    - `answers` 的格式為 `Array<{ questionId, optionId }>`
    - `petType` 是 `petTypes` 中的一個元素

- [ ] **Step 1：先寫會失敗的測試**

```js
import { computeGameResult } from './matchGame';
import { questions, petTypes } from '../data/matchGameQuestions';

const pick = (optionIndex) => questions.map((q) => ({ questionId: q.id, optionId: q.options[optionIndex].id }));

test('不同答案得到不同的配對條件', () => {
  expect(computeGameResult(questions, pick(0)).lifestyle.activityLevel).toBe('high');   // q1=A, q2=A
  expect(computeGameResult(questions, pick(1)).lifestyle.activityLevel).toBe('medium'); // q1=B, q2=B
});
test('毛孩類型取 typeScore 總分最高者', () => {
  expect(computeGameResult(questions, pick(0)).petType.code).toBe('outdoor-buddy');
  expect(computeGameResult(questions, pick(2)).petType.code).toBe('balanced-buddy');
});
test('同一個欄位被多題影響時，以後面的題目為準', () => {
  const answers = [{ questionId: 'q1', optionId: 'A' }, { questionId: 'q2', optionId: 'C' }];
  expect(computeGameResult(questions, answers).lifestyle.activityLevel).toBe('low');
});
test('沒有答完所有題目時丟出錯誤', () => {
  expect(() => computeGameResult(questions, pick(0).slice(1))).toThrow('尚未完成所有題目');
});
```
