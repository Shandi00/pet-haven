**Spec:** [需求與展示範圍](../specs/2026-11-25-需求與展示範圍-design.md)、[新增 API 契約](../../api/新增API契約.md)（**定稿 v1**，§0 是 AI 規則）、[現況架構](../../architecture/現況架構.md)、[backend/AGENTS.md](../../../backend/AGENTS.md)

## Global Constraints

- 回應格式：新 API 成功回 `{ "success": true, "data": ... }`，失敗回 `{ "success": false, "message": "繁中訊息" }`。既有路由保持舊格式，不要改。
- 權限：`admin` 可以處理全部申請；`shelter` 和個人送養者只能處理自己動物的申請（`can_manage_adoption`）。新 API 只能讀寫**目前登入者自己的**資料。
- 設定一律從 `app.config.Settings` 讀取：`gemini_api_key`、`gemini_model`（預設 `gemini-3.8-flash`）、`llm_timeout_seconds`（預設 `8`）。新變數寫進 `backend/.env.example`，值留空。
- 送給 Gemini 的欄位只能是契約 §0 的白名單；log 只記 user id、pet id、`source`、耗時，不記訊息內容、姓名、Email、電話、地址。
- LLM 逾時、錯誤、空回應、JSON 解析失敗，一律改用備援，HTTP 仍回 200；不重試。
- 聊天的 `message` 為 1 到 500 字，`history` 最多 10 則（超過只取最後 10 則），`role` 只能是 `user` 或 `assistant`。
- 測試不打真的 Gemini：一律 monkeypatch `app.services.llm.generate_json`；外部服務都要 monkeypatch。
- 每支新路由都要寫 `summary`（Swagger 自動產生）。

## Review Focus

- 路徑或 body 的 id 不合法（例如 `abc`）：回 400 或 404，不能回 500 → Task 4、Task 7
- Gemini 回傳空字串、不是 JSON、欄位超過長度限制：視同失敗，改用備援 → Task 5 Step 1
- 醫療問題不能呼叫 LLM（測試要斷言 `generate_json` 沒被呼叫）→ Task 6 Step 1
- 送給 LLM 的內容不含使用者的 `name`、`email`、`phone`、`address`（測試要斷言）→ Task 7 Step 1
- 重複執行 `npm run seed`：不能產生重複帳號或動物 → Task 3 Step 4
- 速率限制以「使用者」計算，不是 IP；`APP_ENV=test` 時不限制，測試另外直接測限制器 → Task 5
