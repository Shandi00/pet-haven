# 後端組員任務（T07、T08、T12）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓收容機構能處理自己動物的申請、提供共用固定測資，並建立 AI 聊天後端與 LLM 呼叫層。

**Architecture:** 權限判斷抽成一個純函式，三支認養 API 共用。測資延用 `backend/seed.js`。AI 部分分三層：`llmClient` 只負責呼叫 LLM 和逾時；`aiChatService` 負責拒答、檢索和備援；`routes/ai.js` 負責驗證和速率限制。

**Tech Stack:** Node.js 22、Express 4、Mongoose 7、jest、express-rate-limit（已安裝）。

**Spec:** [需求與展示範圍](../specs/2026-11-25-需求與展示範圍-design.md)、[新增 API 契約](../../api/新增API契約.md)、[backend/AGENTS.md](../../../backend/AGENTS.md)

**開發方式：** 每個 Task 開一個分支，例如 `feat/T07-owner-permission`，完成後發 PR 到 `dev`，照 PR 範本填寫。用 `npm run dev:backend` 啟動後端（需要本機 MongoDB，見根目錄 README）。

## Global Constraints

- 回應格式：成功時回傳 `{ success: true, data }`，失敗時回傳 `{ success: false, message }`，`message` 用繁體中文。
- `admin` 可以處理全部申請；`shelter` 和個人送養者只能處理 `pet.createdBy` 是自己的申請。
- LLM 金鑰只能從 `process.env` 讀取；新的變數寫進 `backend/.env.example`，值留空。
- 送給 LLM 的內容不含姓名、Email、電話、地址；log 裡也不能有這些資料。
- LLM 逾時上限從 `LLM_TIMEOUT_MS` 讀取，預設 `8000`。逾時時不回錯誤，改回傳備援內容。
- 聊天的 `message` 為 1 到 500 字，`history` 最多 10 則，`role` 只能是 `user` 或 `assistant`。

## Review Focus

- `:id` 不是合法的 ObjectId（例如 `abc`）：應該回 400 或 404，不能回 500 → Task 1 Step 6
- 申請對應的動物已被刪除（`adoption.pet` 為 null）：回 404，不能當掉 → Task 1 Step 1
- `pet.createdBy` 有時是 ObjectId、有時是 populate 後的物件：兩種都要判斷正確 → Task 1 Step 1
- LLM 回傳空字串：視同失敗，改用備援內容 → Task 4 Step 1
- 重複執行 `node seed.js`：不能產生重複帳號 → Task 3 Step 4

  - `aiChatService.answer({ message, history }) -> Promise<{ reply, sources, actions, refused, source }>`，格式同 [API 契約](../../api/新增API契約.md) 第 4 節。
  - `POST /api/ai/chat`

- [ ] **Step 1：先寫會失敗的測試**（mock `../services/llmClient` 和 `../services/knowledgeBase`）

```js
test('醫療問題直接拒答，不呼叫 LLM', async () => {
  const r = await answer({ message: '我的狗一直嘔吐怎麼辦', history: [] });
  expect(r.refused).toBe(true);
  expect(r.sources).toEqual([]);
  expect(llmClient.generate).not.toHaveBeenCalled();
});
test('知識庫查不到時不編造，也不呼叫 LLM', async () => {
  knowledgeBase.search.mockResolvedValue([]);
  const r = await answer({ message: '火星上可以養狗嗎', history: [] });
  expect(r.sources).toEqual([]);
  expect(r.reply).toMatch(/沒有.*資料/);
  expect(llmClient.generate).not.toHaveBeenCalled();
});
test('有資料時回答並附上來源', async () => {
  knowledgeBase.search.mockResolvedValue([{ id: 'faq-cat-001', title: '新手養貓準備清單', content: '…' }]);
  llmClient.generate.mockResolvedValue('建議先準備貓砂盆…');
  const r = await answer({ message: '第一次養貓要準備什麼', history: [] });
  expect(r.source).toBe('ai');
  expect(r.sources).toEqual([{ title: '新手養貓準備清單', ref: 'faq-cat-001' }]);
  expect(r.actions.length).toBeGreaterThan(0);
});
test('LLM 逾時改用備援內容', async () => {
  knowledgeBase.search.mockResolvedValue([{ id: 'f1', title: 't', content: 'c' }]);
  llmClient.generate.mockRejectedValue(new Error('timeout'));
  const r = await answer({ message: '第一次養貓要準備什麼', history: [] });
  expect(r.source).toBe('fallback');
  expect(r.reply).toBe('小幫手暫時無法回答，請稍後再試');
});
test('LLM 回傳空字串視同失敗', async () => {
  knowledgeBase.search.mockResolvedValue([{ id: 'f1', title: 't', content: 'c' }]);
  llmClient.generate.mockResolvedValue('   ');
  expect((await answer({ message: '養貓', history: [] })).source).toBe('fallback');
});
```
